Suggested delivery slices

Slice A — FE-only follow-ups FE-ONLY · 5 pts

Pure frontend, can ship without any backend coordination. Reasonable next PR.

ItemNotes
Lift Timeframe control to terminal header Move <TimeframeToggle /> out of MasterChart.tsx and into the terminal page header next to the breadcrumb. Cosmetic now, but required before the future Order Book and Tape can subscribe to the same TF.
Terminal sub-panel reorg Use lightweight-charts panes API to put OI line + Volume bars in one pane and Liquidation bars + Funding rate line overlay in another. Drops the standalone funding pane. No backend work — all series already arrive in ChartInitPayload.

Slice B — Cheap backend fields FE-LIGHT · 7 pts

One small additive field per item on the dashboard endpoint; trivial FE rendering. Good "warm-up" work for the screener backend.

ItemBackend ask
Market-cap filter (3 pts) Add marketCap to each pair record. FE adds a min/max numeric filter to Filters.tsx.
Volume Spike % (4 pts) Add volume_spike_pct = vol_current / vol_24h_avg × 100. Pre-computed server-side avoids a 24h rolling window on the client. FE just renders a column with color thresholds.

Slice C — Multi-exchange foundation BE-HEAVY · 7 pts

Unblocks the user's stated MEXC pain point. Touches data ingestion, so worth scheduling next after Slice B.

  • Add exchange field on AssetPair (Binance default; MEXC second).
  • Server fans out per-exchange ingestion; same DTO shape returned, just tagged.
  • FE adds a single <select> control + filter predicate (2 pts).

Slice D — Analysis terminal upgrades BE-HEAVY · 27 pts

The high-value spec items — what makes the terminal feel like Velo / Coinglass. Each is its own multi-day initiative; sequence them by user impact.

ItemTotalWhy expensive
Order Book L2 panel 13 Live depth WS feed per asset, price-grouping control, depth bar rendering, throttled updates.
Time & Sales tape 7 Full prints stream replaces the current "large only" mock. Backpressure + windowed buffer on the client.
Infinite history loader 7 Paged history endpoint (?before=<ts>); FE prepend flow already stubbed in MasterChart.tsx.

Slice E — Differentiators BE-HEAVY · 47 pts

Large initiatives, each a roadmap item on its own. Schedule individually, not as a slice.

  • P1 Pattern recognition (10) — backend detection job + tagged events; FE renders badge + tooltip.
  • P2 Telegram alerts (16) — chart context menu, alert-rule modal, management view, server-side scheduling + Telegram bot integration.
  • P2 On-chain events (16) — depends on an on-chain indexer (Nansen / Arkham / custom). Largely blocked on data source decision.
  • P0 Footprint chart (21) — per-price-level tick aggregation server-side, custom renderer client-side. The single largest item.

Recommended sequence

  1. Slice A (FE-only, 5 pts) — clean up while backend ramps.
  2. Slice B (FE-light, 7 pts) — proves the dashboard endpoint contract on small fields.
  3. Slice C (Exchange, 7 pts) — unlocks MEXC, the user's headline complaint.
  4. Slice D part 1: Order Book (13 pts) — biggest UX gain in the terminal.
  5. Slice D part 2 + 3: Tape, History loader (14 pts).
  6. Slice E items — schedule individually as standalone roadmap initiatives.

Total remaining: ~29 FE points + ~81 BE points across 12 gaps. Slices A→D account for the spec-critical work (~46 pts). Slice E is differentiation that can lag without breaking the core analyst workflow.
