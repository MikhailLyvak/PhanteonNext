1. Executive summary

PanScreen is a real-time crypto futures screener for professional scalper traders. It tracks 16 Binance USDT-perp pairs and surfaces live OHLCV, CVD (cumulative volume delta), liquidations, funding rates, and open interest. The UI is split into two screens: a dense screener table and a deep-dive analysis terminal with a 6-pane synchronized chart plus real-time liquidations and large-trades feeds. The frontend is mostly thin glue — heavy lifting (footprint heatmap rendering, infinite scroll over 6000-candle pages, multi-stream WS multiplexing) lives in a few key components.

3. Core features

Screener (dashboard)

  • Live table of 16 USDT-perp pairs, updated by WebSocket every ~60 s.
  • Sort by any column (asc/desc), default = OI desc.
  • Text filter + preset buttons (only "All" implemented today).
  • Period toggle (1h / 4h / 24h) changes which historical close is used for % change.
  • Row click → navigates to /terminal/{pair}.

Terminal (chart + feeds)

  • MasterChart — 6 stacked panes, shared time axis:
    1. Candlesticks + volume bars
    2. Footprint heatmap overlay (toggleable) — buy/sell volume per price level
    3. CVD line
    4. Liquidations histogram (buy green / sell red)
    5. Funding rate histogram
    6. Open Interest line
  • 6 timeframes: 1m, 5m, 15m, 1h, 4h, 1d.
  • Infinite backward scroll: pages of 6000 candles prepended on demand.
  • Forward edge tails live updates from the WebSocket.
  • LiquidationsFeed — last 50 individual liquidation events (symbol, side, price, volume, ts).
  • TradesFeed — last 50 "large" trades (filtered by EMA × 12 volume threshold).

AssetPair

interface AssetPair {
  id: number;
  code: string;       // "BTCUSDT"
  coin: string;       // "BTC"
  type: string;       // "USDT"
  tick: number;

}

DashboardAssetData (server payload per pair)

type DashboardAssetData = {
  ohlcv:    { close_latest, close_1h?, close_4h?, close_24h? };
  oi:       { ointerest_latest, ointerest_1h?, ointerest_4h?, ointerest_24h? };
  liquidations: {
    buy_turnover_1h?,  sell_turnover_1h?,  total_turnover_1h?,
    buy_turnover_4h?,  sell_turnover_4h?,  total_turnover_4h?,
    buy_turnover_24h?, sell_turnover_24h?, total_turnover_24h?
  };
  cvd:      { cvd_1h?, cvd_4h?, cvd_24h? };
  funding?: { close_latest };
  tick: number;
  precision: number;
};

Chart data

  • OHLCV candle: { time, open, high, low, close, volume }
  • Footprint frame: { time, data: { [price_level]: { b: buy_vol, s: sell_vol } } }
  • CVD point: { time, value }
  • Liquidations bar: { time, buy_volume, sell_volume }

7. Auth model

panscreen has no auth. All endpoints are public, frontend has no login. In PhanteonNext, the port must be gated behind: (a) ProtectedRoute (logged-in only) and (b) the subscription.screener_access boolean from src/api/Subscriptions/getSubscriptions.ts. Users without the flag should be redirected to /paywall.

8. Real-time architecture

  • 100 % WebSocket-driven after the initial REST snapshot. No polling.
  • Backend broadcasts /ws/all snapshots every 60 s — the dashboard merges incoming events into rows by pair.
  • Per-pair streams (/ws/chart, /ws/liquidations-stream, /ws/trades-stream) are subscribed only on the terminal page and torn down on unmount.
  • Event envelope is always { event: string, data: object }.
  • The chart stream sends a large "init" payload (6000 candles + footprints + CVD + liquidations) and then incremental updates per bar close / per event.

9. Sophisticated / non-trivial pieces

Footprint heatmap plugin

Custom lightweight-charts plugin renders per-price-level buy/sell volume as colored cells inside each candle.

Infinite backward scroll

When the visible range hits the left edge of loaded data, fetch 6000 more candles, prepend without losing the user's pan/zoom.

Multi-pane sync

6 stacked panes share the time axis; legend updates on crosshair move across all panes.

Period-aware % change

Dashboard reads close_1h, close_4h, close_24h from the snapshot and computes the % delta client-side based on the selected period.

Generic WS hook

useWebSocketFeed accepts a URL + transformMessage + maxItems — reused by trades feed and could replace ad-hoc subscriptions elsewhere.
