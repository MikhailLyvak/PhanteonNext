1. Overview

The PanScreen UX will be reproduced inside the PhanteonNext cabinet as two new routes under src/app/myCabinet/screener/, wrapped by the existing ProtectedRoute plus a new client-side screener_access subscription check. All data — table rows, candles, footprints, CVD, liquidations, funding, OI, large trades — is served by static fixture modules in src/lib/screener/mock/ so the entire UI runs without any HTTP/WS calls. Each fixture module exports an async function (getDashboardSnapshot(), getChartInit(pair, tf), subscribeLiquidations(pair, cb), etc.) that mirrors the eventual real signature; future-session work swaps the fixture body for a real Axios call or WS subscription without touching component code. Styling uses Tailwind 3.4 utility classes plus SCSS modules for chart-pane backgrounds, following the existing cabinet design tokens (#D2D2FF accent, #242433 panel, dark background, bold titles). The chart is rendered with lightweight-charts@^5.0.8 (newly added) on a 6-pane synchronized layout; the heatmap is a custom plugin reproduced verbatim from panscreen but fed by mock footprint frames.

// src/lib/screener/types.ts
export interface AssetPair {
  id: number;
  code: string;       // "BTCUSDT"
  coin: string;       // "BTC"

  tick: number;
  precision: number;
  iconUrl: string;    // resolved CoinGecko URL
}

export type Period = '1h' | '4h' | '24h';
export type Timeframe = '1m' | '5m' | '15m' | '1h' | '4h' | '1d';

export interface DashboardAssetData {
  ohlcv:    { close_latest: number; close_1h?: number; close_4h?: number; close_24h?: number };
  oi:       { ointerest_latest: number; ointerest_1h?: number; ointerest_4h?: number; ointerest_24h?: number };
  liquidations: {
    buy_turnover_1h?: number;  sell_turnover_1h?: number;  total_turnover_1h?: number;
    buy_turnover_4h?: number;  sell_turnover_4h?: number;  total_turnover_4h?: number;
    buy_turnover_24h?: number; sell_turnover_24h?: number; total_turnover_24h?: number;
  };
  cvd:      { cvd_1h?: number; cvd_4h?: number; cvd_24h?: number };
  funding?: { close_latest: number };
  tick: number;
  precision: number;
}

export interface Candle          { time: number; open: number; high: number; low: number; close: number; volume: number }
export interface FootprintFrame  { time: number; data: Record<string, { b: number; s: number }> }
export interface CvdPoint        { time: number; value: number }
export interface LiquidationBar  { time: number; buy_volume: number; sell_volume: number }
export interface FundingBar      { time: number; value: number }
export interface OIPoint         { time: number; value: number }

export interface ChartInitPayload {
  candles: Candle[];            // ~200 entries
  footprints: FootprintFrame[]; // ~200 entries, 10-18 price levels each
  cvd: CvdPoint[];
  liquidations: LiquidationBar[];
  funding: FundingBar[];
  oi: OIPoint[];
}

export interface LiquidationEvent { ts: number; symbol: string; side: 'buy'|'sell'; price: number; volume: number }
export interface TradeEvent       { ts: number; symbol: string; side: 'buy'|'sell'; price: number; volume: number; isLarge: true }

Row counts:

  • dashboard.ts: 16 rows (one per pair).
  • chart.ts: ~200 candles per (pair, timeframe), generated lazily on first call and memoised. Footprint frames: one per candle, 10–18 price levels each.
  • feeds.ts: 50 seed events each for liquidations & trades, then 1 event every 1.5–4 s while subscribed.

6. Component breakdown

AssetsTable

  • Client component. On mount: await getDashboardSnapshot() → local rows state.
  • Subscribes to useScreenerStore for period, searchTerm, sortKey, sortDir.
  • Derives display rows: filter by searchTerm (case-insensitive substring on code/coin), compute period-aware deltas, sort.
  • Row click → router.push('/myCabinet/screener/terminal/' + code).
  • TODO(real-data): replace getDashboardSnapshot() with Axios GET /api/screener/dashboard and subscribe to /ws/all for live merge.

MasterChart

  • Client component. Props: pair: AssetPair.
  • Reads timeframe + heatmapVisible from useTerminalStore.
  • useEffect creates a single IChartApi with 6 panes via addPane() (lightweight-charts v5): candle+volume, heatmap overlay (custom series), CVD line, liquidations histogram (buy/sell), funding histogram, OI line.
  • On (pair, timeframe) change: await getChartInit(pair.code, timeframe) → setData on each series.
  • Shared crosshair + legend overlay updates via subscribeCrosshairMove.
  • TODO(real-data): replace getChartInit() with WS /ws/chart/{pair}?tf={tf} init payload + incremental update events.
  • TODO(real-data): "Load older" button currently no-ops with a console warning.

HeatmapPlugin

  • Implements ICustomSeriesPaneView<Time, FootprintCellData> — renderer(), update(), priceValueBuilder(), defaultOptions().
  • Pure rendering: for each footprint frame, draws colored rects at price-level y-positions across the candle's x-span. Color = rgba(buy_green, alpha=clamp(b/(b+s))) / rgba(sell_red, alpha=clamp(s/(b+s))).
  • Reproduced from panscreen/.../HeatmapPlugin.ts with v5 API renames.

LiquidationsFeed

  • Client component. Props: pair: AssetPair.
  • useEffect: const unsub = subscribeLiquidations(pair.code, evt => setEvents(p => [evt, ...p].slice(0, 50))). Cleanup calls unsub.
  • Seeded with 50 events from the mock.
  • Row layout: ts (HH:MM:SS), side-colored dot, price, formatUsdShort(volume).
  • TODO(real-data): swap mock subscribe for new WebSocket(WS_BASE + '/ws/liquidations-stream/' + pair.code).

TradesFeed

  • Identical pattern to LiquidationsFeed, fed from subscribeTrades.
  • TODO(real-data): /ws/trades-stream/{pair}.

Filters

  • Search input bound to searchTerm.
  • PeriodToggle writes Zustand.
  • Preset buttons: only "All" wired; others disabled with title="Coming soon".

7. Routing & auth gate

Cabinet root already redirects unauthenticated users at the server level via src/app/myCabinet/layout.tsx. On top of that, both new pages add a client-side subscription guard:

// src/app/myCabinet/screener/page.tsx (and terminal/[assetId]/page.tsx)
'use client';
return (
  <ProtectedRoute>
    <ScreenerAccessGate>
      {/* cabinet shell: BreadCrump + Sidebar + content */}
      <Filters />
      <AssetsTable />
    </ScreenerAccessGate>
  </ProtectedRoute>
);

ScreenerAccessGate behavior:

  1. useUserStore to read the user.
  2. useQuery (already-present @tanstack/react-query) → getSubscriptions() once.
  3. If any active Subscription.screener_access === true, render children.
  4. Otherwise router.replace('/paywall').
  5. Loading state: small cabinet-style <Loader/>.

Same gate wraps the terminal page.

8. Styling approach

  • Tailwind 3.4 utilities for layout, spacing, typography. Cabinet palette: page bg #1A1A28, panel #242433, accent text #D2D2FF, success #4ADE80, danger #F87171, muted #98A0B3. Headings font-bold text-xl md:text-3xl text-[#D2D2FF] to match tradingBots/page.tsx.
  • SCSS modules:
    • Screener.module.scss: pane min-heights for the 6 chart panes (.pane--candles { min-height: 360px }, .pane--cvd { min-height: 90px }, etc.), sticky table header with subtle border, hover row highlight rgba(210,210,255,0.06).
    • Feeds.module.scss: monospace ts column, .row--buy { color: #4ade80 }, .row--sell { color: #f87171 }, 50-row scroll container max-height: calc(100vh - 240px); overflow-y: auto.
  • Dark theme only. No light-mode variant.
  • Coin icon: next/image 24×24, rounded-full, onError fallback to <span>{coin.slice(0,3)}</span>.
  • Mobile: dashboard table is horizontal-scrollable. Terminal page hides the right column under lg:hidden; chart fills width.
